# Patches

| File | Applies to | Use |
|---|---|---|
| `exllamav3-rdna4.patch` | exllamav3 dev @ f1cf869 | Everything. This is what `setup/build_exllamav3.sh` applies. |
| `tabbyapi-allow-rdna3-rdna4.patch` | tabbyAPI @ f07131c | Lets TabbyAPI load exllamav3 on gfx11/gfx12 GPUs. |
| `features/*.patch` | exllamav3 dev @ f1cf869 | The same work split by feature, for reading and review. |

Only the combined patch is guaranteed to apply and to give the tree we tested. It is
`git diff f1cf869 <work branch>`, generated by `setup/regen_patches.sh`, and touches source, docs and one test
(`test_gdn_replay.py`) only.

The feature patches were cut at different points of the work. On a clean f1cf869, applying them in the order below
works and gives the combined tree except for two small hunks of the GEMV over-read fix (in `exl3_gemv_kernel_rdna.cuh`
and `exl3_gemv_tiles_rdna.cuh`), which only the combined patch has. turboderp fixed the same over-read upstream
independently (cc50bbb).

1. `exllamav3-gfx12-wmma-multirow-gemv.patch`: gfx12 WMMA GEMV for 2-8 rows (draft verification), `EXL3_GEMV_WMMA=1`.
2. `exllamav3-rocm-graph-reinstantiate.patch`: re-instantiate HIP graphs every 100k node updates (`EXL3_GRAPH_REINST`).
3. `exllamav3-rdna4-decode-attention-gqa.patch`: whole-GQA-group split-decode attention and the Q4W kernel
   (`EXL3_DEC_GROUP`, `EXL3_DEC_Q4W`, `EXL3_DEC_*` tuning).
4. `exllamav3-review-fixes.patch`: fixes from the first code review (`notes/reviews.md`).
5. `exllamav3-gdn-accepted-input-replay.patch`: DeltaNet accepted-input replay (`EXL3_GDN_REPLAY=1`) with its test.

See the main README for what each one does and what it measured.
